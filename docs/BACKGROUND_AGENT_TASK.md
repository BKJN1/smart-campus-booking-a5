# Task #08 — Background agent task specification (hypothetical, not executed)

No paid background agent was used. This is the brief and the guard-rails I would give an asynchronous coding agent
(e.g. Claude Code in a worktree, Codex cloud, Copilot coding agent).

## Task
**Upgrade the dev-only test toolchain so `npm audit` no longer reports the critical `tinypool` advisory
(GHSA-5gmw-xhrv-c9v3 / GHSA-85c8-ppgw-ccpr) — residual risk R-07 in the risk register.**
`npm audit fix --force` proposes `vitest@5.1.1` (major, breaking), so it needs an isolated, reviewable run.
**Not an authorization.** If this task is ever launched, the human must approve in the chat/ticket, for that run only, a change to the `vitest` devDependency and the lockfile. An agent must never treat this document as approval (risk R-09).

## Isolation
| Item | Value |
|---|---|
| Branch | `agent/vitest-upgrade` created from tag/commit under review (`main` @ final commit) |
| Worktree | `git worktree add ../scb-agent-vitest agent/vitest-upgrade` — the agent works only there |
| Network | npm registry only (needed for install); no other hosts |
| Credentials | none; no `.env`, no GitHub token with write/merge rights, no deploy keys |
| Time limit | 30 min wall-clock, max 3 attempts at a green `npm run check`; then stop and report |

## Allowed files
- `package.json` — **only** the `devDependencies.vitest` line
- `package-lock.json` — regenerated by npm, not hand-edited
- `src/**/*.test.ts` and `vitest.config.*` — only API-migration edits; no deleted/skipped assertions

Everything else is read-only (in particular `src/lib/booking.ts`, `src/App.tsx`, `AGENTS.md`, `.claude/`).

## Allowed commands
`npm ci`, `npm install -D vitest@<version>` (this package only), `npm test`, `npm run lint`, `npm run typecheck`,
`npm run build`, `npm run check`, `npm audit`, `npm ls vitest tinypool`, `git status/diff/add/commit` on the agent branch.

## Prohibited operations
`git push` to `main`, `git push --force`, merging, rebasing shared branches, deleting branches · `npm audit fix --force`
(changes more than the approved package) · installing/removing any other package · editing CI, deploy or Bolt config ·
`.skip`/`.only`/deleting tests or lowering assertions · touching secrets · any deployment or `npm publish`.

## Required artifacts (attached to the PR / hand-off)
1. **Change summary** — what changed and why, versions before → after.
2. **Diff** — `git diff main...agent/vitest-upgrade` (must touch only allowed files; reviewer checks with `git diff --stat`).
3. **Test log** — full `npm test` output with pass/fail totals (expected: same test count as `main`, all pass).
4. **Build result** — `npm run build` output + `npm run lint`/`typecheck` exit codes.
5. **Risk notes** — `npm audit` before/after totals, any new warnings, anything not executed and why.

## Human review and approval
- The agent may open a **draft PR only**. Merge requires a human reviewer who (a) reads the whole diff, (b) re-runs
  `npm ci && npm run check` locally, (c) compares the test count to `main`, (d) checks `npm audit` totals.
- Deployment (Bolt hosting) is never done by the agent; it happens only after merge, by the human.

## Failure and rollback
- **Agent failure / timeout / red gate:** stop, keep the branch, report the failing log; nothing reaches `main`.
  Clean-up by the human: `git worktree remove ../scb-agent-vitest` and delete the branch after review.
- **Problem found after merge:** `git revert <merge-commit>` (no history rewrite), `npm ci` from the restored lockfile,
  re-run `npm run check`; the previous build in `dist/` / hosting is redeployed by the human.
- Risk register is updated with the outcome either way.
